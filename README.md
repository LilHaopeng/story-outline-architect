# 小说大纲架构师 · Story Outline Architect

面向中文小说的大纲规划 Agent Skill：从最初想写的体验出发，将人物、情节、关系与阶段目标组织成可展开、可审查、可追踪的大纲。当前版本 **v1.3.0**。

基本叙事单元：

`目标 → 冲突 → 选择 → 代价 → 后果 → 新状态`

## 能做什么

- **从构思逐层开纲**：建立 Story DNA、五轨故事架构、故事弧、剧情段、章纲，以及按需启用的近期场景蓝图。
- **保留创作初衷**：保存期待场面、核心追读问题与类型承诺，让结构细化持续服务本书的核心体验。
- **从人物生出情节**：把经历、信念、渴望、恐惧、底线与惯用应对转化成有依据的行动、冲突和选择。
- **安排关系与情绪变化**：按关系、成长、解谜、求生、事业等实际驱动力组织主辅线，反推高潮积累，规划回报与人物高光。
- **支持长篇持续推进**：拆解卷/Arc 目标，保留阶段成果，形成新的行动条件与压力；采用近期细、中期分段、远期保留锚点的滚动视野。
- **维护因果与版本**：检查父子引用、人物知识、世界观版本、状态与伏笔，修订已锁内容时追踪下游影响，并生成带 SHA-256 清单的版本快照。
- **汇编阅读版大纲**：完成指定范围后，通过宿主提供的文档能力汇编 DOCX，保留全部当前有效信息并进行渲染与视觉核对。

适用于新建、扩展、审计、修复、变更和锁定大纲。本技能专注于规划，不直接代写小说正文；结构校验不代表文学质量或情绪效果已经通过。

## 六层结构

| 层级 | 主要任务 | 常用产物 |
|---|---|---|
| L0 Story DNA | 明确核心故事、初衷、追读问题与终局 | `大纲/00_故事DNA.md` |
| L1 故事架构 | 协调情节、人物、冲突、信息与主题 | `大纲/01_故事架构.md` |
| L2 故事弧 | 设计阶段目标、选择与不可逆变化 | `大纲/故事弧/ARC-*.md` |
| L3 剧情段 | 安排局部问题、积累、升级与回报 | `大纲/剧情段/SEQ-*.md` |
| L4 章纲 | 落实事件、目标、信息、选择和章末推动力 | `大纲/细纲_第XXX章.md` |
| L5 场景蓝图 | 为近期复杂场景安排具体行动与转折 | `大纲/场景/`，按需创建 |

篇幅与复杂度共同决定深度：`compact` 适合轻量探索，`standard` 适合普通长篇，`deep` 适合多线、强反转或复杂规则项目。无需让所有故事维护全部台账。

## 安装

在具备 `skill-installer` 的 Codex 环境中，可以发送：

```text
$skill-installer 请从 https://github.com/LilHaopeng/story-outline-architect 安装 skills/story-outline-architect
```

也可下载或克隆仓库，将 `skills/story-outline-architect/` 整个文件夹放入所用宿主的技能目录。应保留 `SKILL.md`、`references/`、`scripts/`、`agents/` 和 `LICENSE`；实际目录与启用方式以宿主要求为准。更新已有自定义版本前保留副本。

## 开始使用

```text
使用 $story-outline-architect 规划我的小说大纲。
先根据我已有的材料整理创作初衷、核心追读问题和 Story DNA，
再讨论主线、人物选择与故事弧，不要直接写正文。
本次先做到 L2，所有未确认方案标为草案。
```

关系驱动的故事可以要求：围绕信任、理解与边界，说明每段共同事件怎样改变双方的认知和下一次行动。

成长或事业驱动的故事可以要求：从阶段目标反推行动，写清保留成果、瓶颈变化、新责任及下一阶段为何开始。

已有世界观时，提供其来源和版本。技能优先读取世界观接口，将计划中的未来变化与当前正典分别记录；不会仅为方便剧情添加临时规则豁免。

## v1.3.0 补充的生成方法

详细方法见 [从核心体验生成情节](skills/story-outline-architect/references/story-generation.md)：

1. 将创作初衷与期待场面保存为后续规划持续读取的依据，区分梗概、悬念与主题。
2. 用“经历—信念—惯用应对—冲突—选择”推导人物反应，让高光有行动与能力依据。
3. 按故事驱动力组织主辅线，连接外部结果与关系、成长等实际变化。
4. 通过“积累—触发—选择—回报—后果”倒推关键高潮，再按时间顺序复核动机、信息与因果。
5. 将回报对应到此前的读者期待，按作品调性选择理解、尊重、能力验证、反击或告别等形式。
6. 将卷/Arc 目标落实为可累积的阶段成果与后续承接，避免反复归零或只增加数字。

新体验字段用于辅助生成。旧项目仍可沿用原结构与锁版流程，不因技能升级自动迁移或改写历史快照。

## 脚本与运行依赖

三个大纲脚本仅使用 Python 标准库；需要可运行这些脚本的 Python 3 环境。代码包含现代类型注解，本次测试运行于 Python 3.14。

在仓库根目录运行，替换命令中的项目路径：

```bash
python skills/story-outline-architect/scripts/init_outline_project.py --root <项目根> --title <书名> --mode standard --dry-run
python skills/story-outline-architect/scripts/validate_outline.py --root <项目根> --scope dna --generation-checks
```

初始化只创建缺失文件；去掉 `--dry-run` 后才会实际创建。`--generation-checks` 仅提示新增 L0 体验字段是否缺失或为空，不能检查情绪感染力。严格校验与锁版要求见 [渐进锁定与大纲变更](skills/story-outline-architect/references/change-control.md)；创建真实锁版前需要用户明确确认。

`story-codex-core` 和 `story-world-architect` 按技能中的条件参与已有项目预检或世界观交接。最终 DOCX 汇编、渲染与视觉核对需要宿主提供 `documents` 或用户明确指定的等效文档工作流，以及相应运行依赖。本仓库不捆绑这些独立技能，也不包含独立 DOCX 构建器。
