# 小说大纲架构师

把大纲做成可执行的故事模型，而不是事件摘要。基本叙事单元是：

`Goal → Conflict → Choice → Cost → Consequence → New State`

人物选择必须产生代价，代价必须改变后续可用的状态；世界规则、偶发事件或他人行动可以触发剧情，但不能替代主要人物持续作出选择。

先锚定作者想写的具体体验，再用人物关系、关键事件与阶段后果将它落地，让读者的期待在推进中得到积累、转折与兑现。

## 工作边界

- 专注于构思、大纲架构、审计、修订与版本锁定；进入正文写作时交接给相应的写作流程。
- 先盘点用户材料与现有项目结构。以用户原稿、已确认设定和锁定版本为准；待定项标记为 `[待确认]`。
- 在工作文件中推进新方案；涉及既有核心设定、终局或已锁章节的调整时，先评估下游影响并经用户确认。
- 若用户预先提供世界观，世界硬规则、制度、势力和开篇正典状态由该世界观拥有；本技能引用并选用其中的冲突与种子来规划剧情后果，保持设定体系唯一。
- 兼容现有 `story-*` 项目的 `设定/`、`大纲/`、`追踪/`、`正文/` 目录结构。

## 世界观输入兼容

先判断世界观输入属于哪一种：

1. **版本化接口**：优先读取 `设定/世界观/15_大纲接口.md`，再读取其索引、硬规则、当前状态以及被选中的 `RULE/CON/SEED/REG/CHAR` 来源文件。
2. **结构化设定但无接口**：盘点现有设定文件，提取来源、正典状态、规则、时代危机、结构冲突、人物入口与开放问题，写入 `大纲/世界观引用.md`，无需迁移原文件。
3. **零散笔记或对话设定**：区分已确认事实、世界内传闻与待定假设（标为 `open`）。若设定复杂到需要制度、势力或状态建模，可先配合 `$story-world-architect` 完成交接。
4. **无世界观输入**：在 Story DNA 中建立支撑当前故事所需的最小临时约束（标为 `provisional`），轻装启动。

世界观存在时执行以下契约：

- 创建 `大纲/世界观引用.md`，固定世界观来源、版本/状态、接口文件、正典基准时间、锁定规则、选用冲突、选用种子、允许调整项、禁用假设和待确认项。
- 从世界的压力中定位主角：选择 `CON/SEED` 后再建立人物欲望、身份、债务、关系和两难，让人物困境自然生发于世界规则。
- Story DNA、架构、Arc、Sequence 和 Chapter 按需引用 `RULE/INST/FAC/CON/SEED/WS/REG/CHAR` ID。世界观漏洞统一写 `WLOOP-NNN`，核对世界观中的原始 `LOOP-NNN`；大纲侧裸 `LOOP-NNN` 只表示故事义务，不用于引用世界漏洞。结构化引用的写法与校验范围见 [artifact-contract.md](references/artifact-contract.md)。
- 把大纲计划导致的未来世界变化写入 `追踪/世界状态变化.md`；待正文实际发生并核验后，再由世界观流程并入正典。
- 若剧情构想触及世界观 `hard` 规则边界，明确选择适配剧情、提出世界观变更（WCR）或另开世界分支。
- 世界观版本更新后重新执行兼容审计；若大纲已锁，通过 Change Request 同步下游节点。

## 选择模式与深度

先判断任务模式：

| 模式 | 适用请求 | 主要动作 |
|---|---|---|
| create | 从想法、梗概或设定开纲 | 自上而下建立 L0-L4 |
| expand | 已有总纲，要扩卷纲、剧情段或章纲 | 固定上层后展开目标层 |
| audit | 复核可行性、逻辑、中段、反转或节奏 | 只读诊断，先出报告再改 |
| repair | 用户已授权修大纲 | 从最高受影响层向下重算 |
| change | 修改已锁内容 | 生成 Change Request 和影响矩阵 |
| lock | 用户确认定稿 | 严格校验后创建版本快照 |

再按复杂度选择深度：

- `compact`：短篇、单线或早期探索。完成 L0-L2，合并 L3/L4，保留精简台账。
- `standard`：常规长篇。完成 L0-L4，维护状态、因果、伏笔和未闭环。
- `deep`：多 POV、悬疑、强反转、复杂制度或世界规则。按需启用完整信息/反转、压力曲线与 L5 场景蓝图。

## 选择故事驱动力

从用户材料判断本书主要靠什么吸引读者：关系、成长、解谜、求生、事业或其他；混合型写明主次。

创建或修复核心体验、人物关系、主辅线、开篇窗口、高潮和阶段循环时，读取 [story-generation.md](references/story-generation.md)，按本次范围启用相应方法：

- **L0**：保存创作初衷、代表性期待场面、简短梗概和核心追读问题；悬念与主题分别表述。
- **L1-L2**：从人物经历与信念生成选择，解释核心人物因何联系、如何相互影响；按主导驱动力组织主辅线、关键高潮、人物高光和阶段成果。镜像与误读按需使用。
- **L3-L4**：按体量、叙事形式与类型承诺划定开篇试读窗口，安排人物吸引力、卖点呈现与首次体验验证；用精简章纲或按需展开的字段落实事件，“本章戏眼”纯可选。

详细记录优先写入现有 DNA、架构、Arc/Sequence 和台账，保持文件结构整洁。

## 六层模型

| 层级 | 回答的问题 | 默认产物 |
|---|---|---|
| L0 Story DNA | 这是谁的什么故事，最终回答什么 | `大纲/00_故事DNA.md` |
| L1 Story Architecture | Plot、Character、Conflict、Information、Theme 如何同步推进 | `大纲/01_故事架构.md` |
| L2 Arc Architecture | 每个大弧线造成什么不可逆变化 | `大纲/故事弧/ARC-*.md` |
| L3 Sequence | 2-6 章左右的局部问题如何提出、升级、解决并留后果 | `大纲/剧情段/SEQ-*.md` |
| L4 Chapter Outline | 本章功能、选择、代价、信息、戏眼与章末推动力 | `大纲/细纲_第XXX章.md` |
| L5 Scene Blueprint | 场景内权力、行动、转折如何变化 | `大纲/场景/*.md`，仅对近期复杂章节按需创建 |

具体字段、兼容目录和台账格式见 [artifact-contract.md](references/artifact-contract.md)。创建或扩写任何层级前读取该文件。

## 分阶段工作流

### 0. 盘点与可行性预检

1. 盘点已有来源、当前权威文件、已锁内容、版本差异与待补材料。
2. 若有世界观索引、接口、锁定 manifest 或其他设定来源，先建立 `大纲/世界观引用.md` 并固定所用版本。
3. 确认目标读者/平台、体量、类型承诺、主导驱动力、用户硬约束和本次目标层级。
4. 给出简短预检：`可进入大纲 / 需先补关键决策 / 当前设定不可行`，区分世界硬规则问题、世界—大纲接口问题与故事结构问题。
5. 初始化新项目时可运行 `<skill-dir>/scripts/init_outline_project.py`（仅创建缺失文件，不覆盖已有原稿）：

```text
python <skill-dir>/scripts/init_outline_project.py --root <项目根> --title <书名> --mode <compact|standard|deep>
```

### 1. L0：冻结故事基因

形成 Story DNA，并做可行性压力测试：核心目标是否能支撑预期篇幅；主角欲望、深层需求、阻力、价值矛盾、类型承诺和终局是否互相咬合；独特机制是否能持续产生新选择。已有世界观时，核心阻力、独特机制和持续引擎回指已选 `CON/SEED/RULE` 并说明人物入口。

将创作初衷写成具体的处境、关系或感受，并保存一个代表性期待场面（模型建议的场面注明“候选”）。用约 100 字的核心故事说明人物、触发、追求与主要阻力，再提出读者持续等待回答的问题。向用户展示 L0 与关键待确认项，确认后再批量下钻（若用户希望直接出全案，则标为 `draft` 推进）。

### 2. L1-L2：架构与故事弧

1. 建立五轨总表，将人物弧嵌入 Plot 同步推进。
2. 引用或补足主要人物的决策依据（经历、信念、渴望、恐惧、底线与惯用应对），说明他们因何产生联系，在目标、手段、利益、责任或认知上有哪些互补与分歧，以及如何改变彼此行动。镜像与误读作为可选工具。
3. 从终局反推主要 Arc。每个 Arc 明确起始状态、目标、主要阻力、升级、关键选择、代价、不可逆后果和结束状态。
4. 对关键高潮先明确要回应的期待和高潮后的变化，再反推前置积累、触发与选择。成长/事业线同时规划阶段成果、保留收益、新行动条件与新压力。
5. 为关键转折维护因果依赖表（`追踪/因果依赖.md`）。确认主线、终局和 Arc 顺序后再进入批量下钻。

### 3. L3-L4：剧情段、开篇窗口与章纲

1. **开篇试读窗口**：按体量、章节长度、叙事形式与类型承诺指定本次窗口及涵盖的节点；3–5 章仅作参考，不绑定 `SEQ-001` 或固定动作数。核对人物吸引力、规则/卖点的具体呈现和首次体验验证：悬疑线索、独特互动或局部破局都可以回应本书承诺，不要求先解决一场危机。
2. 每个 Sequence 围绕一个可回答的局部问题，结尾改变目标、规则、权力、关系、资源或信息中的至少一项。先做一个代表性 Sequence 和 1–3 章样例校准粒度，确认后按批次扩展。
3. 长篇采用滚动视野：近期 5–10 章详细并冻结，中期按 Sequence 规划，远期保留 Arc 锚点。
4. L4 默认推荐精简版，将“阻碍与冲突”“决策与代价”“后果与状态变化”分别合并；复杂章节可拆开，也可混用三组写法，校验器接受等价字段组。推进脉络在内容概括和动作序列中择一；“本章戏眼”纯可选，不强制对白、金句或感官装饰。

### 4. L5：按需场景蓝图

当近期章节涉及复杂谈判、推理博弈、多方动作场面或需要直接指导正文下笔时，为接下来 1–3 章按需创建场景蓝图。

### 5. 七视角审计

读取 [audit-rubric.md](references/audit-rubric.md)，依次从 Concept、Story、Character、Conflict、Outline、Logic、Story Doctor 七个编辑视角审查大纲，先列具体节点证据与问题分级（S0–S3），再给最小修复方案。

- **重心分级**：日常 L0–L2 审计聚焦于 S0/S1 阻断项、人物能动性、核心体验承载、开篇吸引力与跨卷追读动力；四项量化诊断比率与 100 分编辑量表作为 `deep` 模式或完整章纲（L4）锁版前的深度体检工具按需启用。
- **证据底线**：未解决的 S0/S1 阻断项不得被总分抵消；材料未展开到对应粒度时，相关指标标为“无法计算”。到期承诺区分已兑现/具体情节重释、附新窗口与理由的显式延期、逾期未处理，延期不计入兑现分子。
- **体验与兼容复核**：检查创作初衷落地、高潮质变、人物高光依据、期待兑现与阶段成果保留；有世界观输入时核对版本同步、ID 引用有效性与状态边界。需要检查 L0 体验字段非空状态时可加 `--generation-checks`。

### 6. 修订与锁定

按 `世界观引用 → L0 → L1 → L2 → L3 → L4 → L5 → 台账` 的顺序向下同步修改。涉及锁定内容时读取 [change-control.md](references/change-control.md)，提供影响范围与最小改动方案。

锁定前运行严格校验：

```text
python <skill-dir>/scripts/validate_outline.py --root <项目根> --scope <dna|architecture|arc|sequence|chapter> --strict
```

经用户确认锁版后创建快照：

```text
python <skill-dir>/scripts/lock_outline.py --root <项目根> --version v1.0 --scope chapter --note "用户确认的大纲版本"
```

### 7. 汇编与 DOCX 最终交付

当本次大纲范围完成并准备最终交付文档时，读取 [docx-delivery.md](references/docx-delivery.md)，将当前全部有效大纲信息汇编为结构清晰的 DOCX（阶段性讨论与滚动修改直接在 Markdown 中进行，无需每轮重做 DOCX）。

1. 盘点并对账世界观引用、Story DNA、故事架构、全部有效 Arc/Sequence/Chapter、按需场景蓝图及启用台账，完整保留细纲信息。
2. 在 DOCX 中标明交付范围、最高完成层、活动视野、大纲版本、世界观来源/版本与覆盖清单（草案标明 `draft`）。
3. 宿主提供文档技能时遵循其规范；其他环境可在具备 Python 文档库、转换器、PDF 渲染器与合适字体时，按通用制作指导构建和检查。本包没有 DOCX 构建、PDF 转换或页面渲染脚本，不承诺在任意沙盒直接生成文档。
4. 默认交付最终 `.docx`，并简要报告版本、覆盖范围与版面核对结果。
