# 大纲产物契约

创建、扩写或修订大纲时读取。本契约让人类可读的 Markdown 同时具备稳定层级、可追踪 ID 和最小机器校验能力。

如何从体验、人物与阶段目标生成情节见 [story-generation.md](story-generation.md)。新增体验字段用于新建项目与用户授权的工作稿增强；旧项目可沿用原结构，锁定快照不因技能升级而补写。

## 1. 权威来源与兼容原则

- 用户原稿、已确认设定、锁定版本优先于模型推断。
- `设定/` 保存世界与人物的稳定事实；`大纲/` 保存计划；`追踪/` 保存随剧情变化的状态与义务；`正文/` 保存已发生的事实。不要在四处重复维护同一事实。
- 预先提供世界观时，优先读取 `设定/世界观/15_大纲接口.md`；`大纲/世界观引用.md` 只固定来源、版本与本书选用项，`追踪/世界状态变化.md` 只保存尚未成为正典的拟议后果。
- `交付/*_小说大纲_*.docx` 是指定大纲版本与完成范围的排版阅读快照，不取代 `大纲/` 和 `追踪/` 的 Markdown 权威来源。
- 已有 `story-long-write` 项目的 `大纲/大纲.md`、`卷纲_第X卷.md`、`细纲_第XXX章.md`、`追踪/伏笔.md`、`时间线.md`、`角色状态.md` 继续有效。新增文件是增强层，不要求迁移旧文件。
- 发现冲突时建立问题条目并标注来源；不得静默选一个版本。
- 缺失但不阻断当前层的信息写 `[待确认]`。会改变核心目标、终局、世界硬规则或主要人物动机的缺失信息必须在下钻前确认。

## 2. 可伸缩目录

```text
{项目根}/
├── 设定/                              # 已有项目继续沿用
├── 大纲/
│   ├── 工作状态.md                    # 当前阶段、深度、活动视野、锁定版本
│   ├── 世界观引用.md                  # 有世界观输入时：来源、版本和本书选用接口
│   ├── 00_故事DNA.md                  # L0
│   ├── 01_故事架构.md                 # L1 + 五轨 + 人物×情节矩阵
│   ├── 大纲.md                        # 可选：兼容既有全书鸟瞰
│   ├── 卷纲_第X卷.md                  # 可选：兼容既有卷纲
│   ├── 故事弧/
│   │   ├── _索引.md
│   │   └── ARC-001_名称.md             # L2
│   ├── 剧情段/
│   │   ├── _索引.md
│   │   └── SEQ-001_名称.md             # L3
│   ├── 细纲_第001章.md                # L4，兼容既有命名
│   ├── 场景/                          # L5，仅按需
│   │   └── CH-001_SC-01_名称.md
│   └── 版本/                          # 锁定快照；不得手改
├── 追踪/
│   ├── 大纲状态.md                    # 核心状态转换
│   ├── 世界状态变化.md                # 大纲拟议后果；不等于当前世界正典
│   ├── 因果依赖.md                    # 关键事件依赖，Story Graph 权威来源
│   ├── 未闭环.md                      # 尚未解决的故事义务
│   ├── 伏笔.md                        # 与既有 story 项目兼容
│   ├── 信息与反转.md                  # 悬疑/强反转项目启用
│   ├── 压力曲线.md                    # 长篇中段或节奏修复时启用
│   ├── 时间线.md                      # 需要时沿用
│   ├── 角色状态.md                    # 需要时沿用
│   └── 大纲变更.md                    # 变更请求与锁定记录
└── 交付/
    └── {项目名}_小说大纲_{版本}.docx
```

`compact` 至少保留 Story DNA、故事架构、故事弧/剧情段索引、状态、因果、未闭环与变更记录。`standard` 再启用伏笔和信息台账。`deep` 才默认创建压力曲线与场景目录。

## 3. ID 与引用规则

| 对象 | 格式 | 示例 |
|---|---|---|
| 故事弧 | `ARC-NNN` | `ARC-003` |
| 剧情段 | `SEQ-NNN` | `SEQ-014` |
| 关键事件 | `EVT-NNN` | `EVT-042` |
| 章节 | `CH-NNN` | `CH-027` |
| 场景 | `CH-NNN-SC-NN` | `CH-027-SC-02` |
| 伏笔 | `F-NNN` | `F-008` |
| 反转 | `T-NNN` | `T-003` |
| 未闭环 | `LOOP-NNN` | `LOOP-012` |
| 状态检查点 | `S-NNN` | `S-006` |
| 变更请求 | `CR-NNN` | `CR-004` |
| 世界硬规则（外部引用） | `RULE-NNN` | `RULE-002` |
| 世界结构冲突（外部引用） | `CON-NNN` | `CON-005` |
| 世界剧情种子（外部引用） | `SEED-NNN` | `SEED-011` |
| 世界状态（外部引用） | `WS-NNN` | `WS-003` |

- ID 一旦进入锁定版本不得重编号；删除对象时标记 `retired`，不要复用 ID。
- L3 必须引用所属 ARC；L4 必须引用所属 ARC 与 SEQ；L5 必须引用所属章节。
- `requires` 只能指向更早建立的事件、状态、规则或信息；`causes` 可以指向尚未展开但已登记的后继对象。
- 因果图从 `追踪/因果依赖.md` 派生。除非项目确实需要程序化图计算，不同时维护一份容易漂移的手写 JSON 图。

## 4. 世界观输入契约（按需）

只有项目预先提供世界观时才创建 `大纲/世界观引用.md`。它必须是指针与选择记录，不得复制整套世界设定：

```markdown
# 大纲世界观引用

- 引用状态：active
- 接口模式：world-first / extracted
- 世界观来源：设定/世界观/世界观索引.md
- 世界观版本/状态：v1.0 / locked
- 接口文件：设定/世界观/15_大纲接口.md
- 正典基准时间：
- 锁定硬规则：RULE-001
- 选用结构冲突：CON-001
- 选用剧情种子：SEED-001
- 允许调整项：
- 禁止假设：
- 待确认：无
- 最近兼容审计：
```

若来源没有版本化接口，`接口模式` 写 `extracted`，列出实际源文件和定位；用户确认前不得把模型归纳升级为 hard canon。若来源有锁版 manifest，可补充 manifest 路径或文件哈希。

大纲计划引发的世界变化记录在 `追踪/世界状态变化.md`：

```markdown
# 拟议世界状态变化

> 本表是剧情计划，不代表当前正典。正文发生并核验后，才可交给世界观流程并入当前状态。

| Change ID | 触发节点 | 前置世界状态 | 人物选择 | 直接后果 | 二阶后果 | 受影响 RULE/FAC/CON | 传播时延 | 可逆性 | 落地状态 |
|---|---|---|---|---|---|---|---|---|---|
```

世界观版本变化后，先比较接口，再检查 Story DNA、五轨、所有引用受影响 ID 的 Arc/Sequence/Chapter 及本表。已锁大纲走 Change Request，不自动覆盖。

## 5. L0：Story DNA 模板

```markdown
# Story DNA

- 状态：draft
- 项目名：
- 创作初衷：最初想写的具体处境、关系或感受及其原因
- 期待场面：代表性体验锚点；标明用户已确认或模型候选
- 核心追读问题：读者持续等待回答的问题
- 主导驱动力：关系 / 成长 / 解谜 / 求生 / 事业 / 其他；混合时说明主次
- 核心故事：这实际上是谁的什么故事
- 主角欲望：他明确想得到什么
- 深层需求：他必须认识或改变什么
- 核心阻力：谁或什么持续阻止他
- 核心矛盾：哪两个价值或目标无法同时满足
- 核心问题：结局必须回答的问题
- 类型承诺：读者因什么进入并持续阅读
- 核心体验：主要情绪与满足机制
- 终局状态：人物、关系和世界与开篇有何本质不同
- 独特机制：区别于同类作品且能重复产出剧情的机制
- 持续引擎：该机制如何在不同阶段制造新目标与代价
- 不可妥协设定：用户明确锁定的事实
- 允许调整项：仍可探索的内容

## 一句话命题

{人物初始信念 + 追求 + 系统性阻力 + 最终必须付代价的选择}

## 可行性压力测试

- 预期体量与支撑理由：
- 中段可改变的游戏规则：
- 终局是否由前序选择导致：
- 最大可信度风险：
- 待确认：
```

L0 保存体验锚点，不编排章节事件。核心故事以约 100 字梗概聚焦人物、触发、追求与阻力；一句话命题表达价值两难，核心追读问题组织读者期待，三者分别起作用。若独特机制只能制造一次惊喜，不能支撑预计体量，应先缩短篇幅或补持续引擎。

新增四项体验字段只作生成辅助。`validate_outline.py --generation-checks` 可提示缺失或空值，即使同时使用 `--strict` 也只给 warning；它不判断初衷与剧情是否一致，不要求旧项目迁移。

## 6. L1：Story Architecture 模板

```markdown
# 故事架构

- 状态：draft
- 开篇状态：
- 终局状态：
- 书级主目标：
- 终局选择：
- 结构策略：强主线 / 弱主线 / 单元剧 / 多线交织 / 其他
- 世界观入口：无 / CON-NNN + SEED-NNN

## 五轨总表

| Arc ID | Plot：外部事件与局势 | Character：信念与选择 | Conflict：对手与权力 | Information：各方知道什么 | Theme：用何种两难体现 | 不可逆状态变化 |
|---|---|---|---|---|---|---|

## Plot Track｜情节轨道

{主目标如何被分解、阻断、改写并最终解决}

## Character Track｜人物轨道

{初始信念 → 挑战 → 抵抗 → 崩溃/反证 → 新认知 → 终局选择}

## Conflict Track｜冲突轨道

{障碍 → 有意志的对手 → 竞争 → 系统性压制 → 不可调和局面}

## Information Track｜信息轨道

{作者真相、读者认知、主要角色认知，以及信息何时改变意义}

## Theme Track｜主题轨道

{不同角色/制度如何通过行动承担相反价值；禁止只靠对白宣布主题}

## 人物 × 情节矩阵

| 关键事件 | 外部后果 | 角色此前信念 | 被迫选择 | 付出代价 | 内在变化 | 后续行为变化 |
|---|---|---|---|---|---|---|

## 人物决策依据（按需）

| 人物/设定来源 | 经历形成的信念与惯用应对 | 渴望、恐惧与底线 | 本故事中的冲突与选择 |
|---|---|---|---|

## 关键高潮与回报（按需）

| 所在节点 | 读者期待与前置积累 | 触发、选择与回报 | 后续变化 |
|---|---|---|---|

## 主支线契约

| 线名 | 服务的书级目标/类型承诺 | 起点 | 交汇或回收点 | 若删除的影响 |
|---|---|---|---|---|
```

每条支线至少要推进主线、人物弧、主题两难或类型承诺中的一项，并在合理时点交汇；纯粹延长篇幅的支线应删减或改造。

人物决策依据引用稳定设定，补充本故事需要的行动推导；关键节点表作概览，详细高潮卡放所属 Arc/Sequence 并用现有 ID 回指。关系驱动时，主支线契约说明共同事件如何改变双方认知、信任、边界或下一次行动；混合型保留其他核心承诺。

## 11. 核心台账

### `追踪/大纲状态.md`

```markdown
# 大纲状态

| State ID | 所在节点 | 人物/身份 | 关系 | 资源/权力 | 信息 | 外部局势/规则 | 威胁 | 来源事件 |
|---|---|---|---|---|---|---|---|---|
```

状态变化只有在后续规划确实读取它时才算有效；写在表里但不影响任何行动不计入状态变化率。

### `追踪/因果依赖.md`

```markdown
# 因果依赖

| Event ID | 所在节点 | requires | trigger | 选择者 | Choice | Cost | causes | New State |
|---|---|---|---|---|---|---|---|---|
```

只登记转折、关键获得/失去、阵营变化、真相揭露、高潮和终局等铰链事件。

### `追踪/信息与反转.md`

```markdown
# 信息与反转

## 知识状态

| 信息 ID | 真相 | 读者知道 | 主角知道 | 对手知道 | 其他关键角色知道 | 最近变化节点 |
|---|---|---|---|---|---|---|

## 反转台账

| Twist ID | Truth | Reader Belief | Character Belief | Evidence | Misdirection | Reveal Trigger | Reinterpretation | 揭示节点 |
|---|---|---|---|---|---|---|---|---|
```

反转必须让旧证据获得新意义；只靠揭晓此前从未存在的新事实，属于补丁而非高质量反转。

### `追踪/伏笔.md`

```markdown
# 伏笔追踪

| ID | Setup | Reinforcement | Planned Payoff / Reframe | Deadline | 状态 | 相关节点 |
|---|---|---|---|---|---|---|
```

状态建议使用 `planned / active / reinforced / resolved / reframed / retired / overdue`。有意识留白用 `retired` 并说明原因，不要伪装成已回收。

### `追踪/未闭环.md`

```markdown
# 未闭环

| Loop ID | 承诺/问题 | 创建节点 | 预期处理窗口 | 处理方式 | 状态 | 若不处理的影响 |
|---|---|---|---|---|---|---|
```

### `追踪/压力曲线.md`

```markdown
# 压力曲线

| 节点 | 外部 | 关系 | 内在 | 资源 | 信息 | 道德 | 主导压力 | 升降理由 |
|---|---:|---:|---:|---:|---:|---:|---|---|
```

分值用于比较相邻节点，不代表客观真值。强度不必单调上升，但压力来源、游戏规则或应对策略应变化。

## 12. 工作状态文件

`大纲/工作状态.md` 至少记录：

```markdown
# 大纲工作状态

- 工作模式：create
- 深度：standard
- 当前最高完成层：L0
- 当前活动视野：CH-001 至 CH-010
- 已确认层级：无
- 最新锁定版本：无
- 最新 DOCX 交付：无
- 权威来源：
- 待确认：
```

每次阶段确认、滚动视野变化或锁定后更新。它只记录流程元信息，不复制故事事实。

## 13. DOCX 最终交付

当本次大纲任务完成时，必须生成 `交付/{项目名}_小说大纲_{版本}.docx`。完整汇编范围、L0–L5 顺序、台账与对象 ID 对账、排版及逐页渲染验收见 [docx-delivery.md](docx-delivery.md)。

DOCX 是派生快照：锁定版从对应版本快照生成；草案版必须标明 `draft`、最高完成层、活动视野、未完成层和待确认项。交付后在 `大纲/工作状态.md` 记录路径、版本、完成范围、日期与 QA 结果。
