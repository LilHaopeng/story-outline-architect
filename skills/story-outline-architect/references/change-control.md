# 渐进锁定与大纲变更

修改已确认内容或创建版本快照时读取。目标是帮创作者在稳固既有成果的同时，为长篇连载或持续打磨保留充足的探索弹性。

## 1. 五种锁定层级

“锁定”并非禁止修改，而是让每一次改动都清晰可见、可评估下游影响：

| 锁定层级 | 覆盖内容 | 调整方式 |
|---|---|---|
| **World Interface Lock**（有世界观时） | 世界观来源、版本、接口、选用 `RULE/CON/SEED/REG/CHAR/WLOOP` 与禁用假设 | 世界观版本更新时执行兼容对账 |
| **DNA Lock** | 核心故事、书级目标、类型承诺、终局问题，以及已确认的初衷与核心体验 | 重大调整前先确认取舍 |
| **Architecture Lock** | 五轨总表、主要人物弧、核心关系张力、Arc 顺序与终局选择 | 通过 Change Request 评估影响后同步 |
| **Rolling Horizon Lock** | 近期 5–10 章的 Sequence 与 Chapter 细纲 | 正文开写后近期冻结，中远期保持弹性 |
| **Version Lock** | 某一时点的完整大纲快照与 SHA-256 清单 | 按约定归档且拒绝同名覆盖；新改动使用新版本号，不是操作系统强制只读 |

## 2. 滚动视野（近细远粗）

- **近期（5–10 章）**：章纲完整，明确冲突、选择与章末推动力，戏眼纯可选，按需配备 Scene Blueprint。
- **中期（若干 Sequence）**：明确每段驱动问题、局势升级、选择代价和状态变化。
- **远期（后续 Arc）**：保留 Arc 锚点、关键高潮方向、终局依赖和重要伏笔回收窗口。

当正文写作产生新的灵感或反馈时，优先在未锁定的中远期序列中消化与承接，保持已发生正文与前置因果的稳固。

## 4. 变更同步流程

1. **定位最高受影响层**：若调整世界观 `hard` 规则或引用版本，从 World Interface 开始评估；若调整书级主目标，从 L0/L1 开始评估。
2. **方案比选**：对比“最小局部改动”与“结构重算”各自的得失，确认后再动手修改。
3. **自上而下同步**：按 `世界观引用 → L0 → L1 → L2 → L3 → L4 → L5 → 台账` 顺序逐层更新，确保父子引用与状态台账一致。
4. **校验与归档**：运行结构校验与语义复核，通过后按需创建新的版本快照。

## 5. 版本号规范

- `v0.x`：探索草案阶段，允许保留 `[待确认]` 事项。
- `v1.0`：首个完成严格校验并锁定的正式版本。
- `v1.x`：不改变 Story DNA、终局因果或世界观硬规则的局部扩写与兼容修订。
- `v2.0`：调整核心目标、终局走向、世界观基线或主要人物弧线的重大重构版本。

## 6. 校验与锁定命令

锁定前执行严格校验（检查必填字段、层级引用与未决占位符）：

```text
python <skill-dir>/scripts/validate_outline.py --root <项目根> --scope chapter --strict
```

确认定稿后创建版本快照：

```text
python <skill-dir>/scripts/lock_outline.py --root <项目根> --version v1.0 --scope chapter --note "版本说明"
```

快照会自动归档所选层级的 `大纲/` 文件、相关 `追踪/` 台账并生成 `manifest.json`（含 SHA-256 校验值）。

技能升级不自动迁移既有大纲，也不补写历史锁定快照。字段精简和世界观引用别名先用于授权的工作范围；锁版引用格式需要变更时仍保留原快照并记录影响。
