# 渐进锁定与大纲变更

修改已确认内容或创建版本快照时读取。目标是减少返工，同时保留长篇创作所需的探索空间。

## 1. 五种锁定

| 锁定 | 内容 | 默认可变性 |
|---|---|---|
| World Interface Lock（有世界观时） | 世界观来源、版本、接口、选用 RULE/CON/SEED 与禁用假设 | 世界版本变化必须兼容审计 |
| DNA Lock | 核心故事、书级目标、类型承诺、终局问题，以及已确认的初衷与核心体验 | 重大变更必须确认 |
| Architecture Lock | 五轨、主要人物弧、Arc 顺序与终局选择 | 通过 Change Request 修改 |
| Rolling Horizon Lock | 接下来 5-10 章的 Sequence/Chapter | 正文开始后冻结；远期仍可调 |
| Version Lock | 某一时点的完整快照与哈希清单 | 不覆盖、不手改 |

不要把“锁定”理解为永不修改。锁定表示任何修改都必须可见、可追踪，并先评估下游影响。

## 2. 远近视野

- 近期：5-10 章，章纲完整，必要时有 Scene Blueprint。
- 中期：若干 Sequence，明确问题、选择、代价和状态变化。
- 远期：只保留 Arc 锚点、终局依赖和关键回报窗口。

正文反馈发生变化时，优先调整未锁的中远期；不得为迁就一个局部好点子偷偷改掉已发生事实。

## 4. 变更流程

1. 找到最高受影响层级。若改变世界观 hard 规则或引用版本，先评估 World Interface；若改变主角书级目标，即使用户只说“改第 20 章”，也从 L0/L1 开始评估。
2. 比较最小改动与结构重算；说明各自保留什么、牺牲什么。
3. 变更用户已确认的核心设定、终局、锁定章节或已写正文前，取得明确确认。
4. 批准后自上而下更新；顺序为 `世界观引用 → L0 → L1 → L2 → L3 → L4 → L5 → 台账`。每改一层同步其子层与台账，禁止只修局部文本。
5. 运行结构校验，再做语义审计。两者通过后才能创建新锁定版本。

技能版本升级本身不改变项目版本或已确认剧情。新增体验字段与生成方法先用于本次授权的工作范围；涉及已锁内容时按同一变更流程处理，不补写历史快照。

## 5. 版本语义

- `v0.x`：探索草案，可有 `[待确认]`。
- `v1.0`：首次完整锁定版本。
- `v1.x`：不改变 Story DNA、终局因果或所用世界观 hard 规则的兼容修订。
- `v2.0`：改变核心目标、终局、所用世界观基线/主要规则或人物弧的结构性重算。

版本目录不得覆盖。需要废弃时保留原快照，并在变更记录中标记 superseded。

## 6. 锁定命令

先严格校验：

```text
python <skill-dir>/scripts/validate_outline.py --root <项目根> --scope chapter --strict
```

用户确认后创建快照：

```text
python <skill-dir>/scripts/lock_outline.py --root <项目根> --version v1.0 --scope chapter --note "确认说明"
```

快照包含所选层级的 `大纲/` 文件、相关 `追踪/` 文件和 SHA-256 manifest；若存在 `大纲/世界观引用.md` 与 `追踪/世界状态变化.md`，一并纳入。脚本拒绝覆盖同名版本；若需新版本，使用新的版本号。
