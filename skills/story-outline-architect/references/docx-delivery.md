# 大纲 DOCX 最终交付指南

在本次大纲任务完成并需要导出完整阅读文档时读取。日常规划与滚动修改继续以 `大纲/` 与 `追踪/` 中的 Markdown 为主；生成的 DOCX 是对应版本与完成范围的排版级汇编文档，便于通读、审稿或团队分享。

## 1. 交付时机与命名

- **常规交付（`create / expand / repair / change / lock`）**：完成目标层级后汇编生成一份完整的 DOCX。
- **审计交付（`audit`）**：按需收录审查范围内的有效大纲、审计诊断、问题分级与修订路线图。
- **版本标识**：已锁定版本从对应快照生成（如 `{项目名}_小说大纲_v1.0.docx`）；未锁定的阶段性方案使用 `draft-YYYYMMDD` 命名并在封面标明草案状态与当前完成视野。
- **进度记录**：生成后在 `大纲/工作状态.md` 记录文件路径、版本、完成层级与日期。

默认输出路径：

```text
{项目根}/交付/{项目名}_小说大纲_{版本}.docx
```

## 2. 汇编前内容对账

汇编前先盘点当前有效内容，确保结构完整、层级对齐：

- **基础与工作状态**：`大纲/工作状态.md`、锁版 manifest、总纲与卷纲（若有）。
- **世界观接口摘要（若有）**：`大纲/世界观引用.md` 中本书实际引用的规则、结构冲突、剧情种子、地域/人物锚点与约束摘要（无需把整部世界设定集全文复制进大纲文档）。
- **核心大纲层级（L0–L5）**：只收录当前版本实际启用的内容；未使用的可选字段不补写。
  - `L0 Story DNA`（含创作初衷、期待场面、百字核心故事、追读问题与主导驱动力）
  - `L1 故事架构`（五轨总表、人物×情节矩阵、人物决策依据与关系张力、关键高潮概览、主支线契约）
  - `L2 故事弧（ARC）`（按顺序完整收录目标、阻力、选择、代价、不可逆后果、阶段保留成果与承接）
  - `L3 剧情段（SEQ）`（驱动问题、升级、选择、后果、章节分配，以及已选开篇试读窗口的设计）
  - `L4 章纲（CH）`（按章节顺序完整收录有效章纲、推进脉络与连续性输入；保留精简/展开格式，戏眼仅在已填写时收录）
  - `L5 场景蓝图（SC）`（收录已创建的近期场景蓝图，按所属章节归组）
- **追踪台账與记录**：实际启用的 `大纲状态.md`、`世界状态变化.md`、`因果依赖.md`、`未闭环.md`、`伏笔.md`、`信息与反转.md`、`压力曲线.md`、`时间线.md`、`角色状态.md` 与 `大纲变更.md`。

成稿后核对 `ARC / SEQ / CH / SC / EVT / F / T / LOOP / S / CR` 及世界观引用 ID 的完整性，确保编号顺序与源文件一致。

## 3. 推荐文档章节结构

按项目实际最高完成层组织章节：

1. **封面**：项目名、文档副标题、大纲版本、状态（`locked` / `draft`）、最高完成层、当前活动视野、世界观版本、生成日期。
2. **阅读与范围说明**：交付范围、结构策略、已完成层级与待展开视野。
3. **故事总览（L0 Story DNA）**：创作初衷、期待场面、核心追读问题、主导驱动力、一句话命题、类型承诺、独特机制、持续引擎与可行性评估。
4. **世界观接口摘要（按需）**：来源版本、锁定硬规则、选用冲突与种子、开篇基准状态。
5. **故事架构（L1）**：书级目标、开篇/终局状态、五轨总表、人物决策依据与关系张力、人物×情节矩阵、主支线契约。
6. **故事弧（L2）**：按 `ARC` 顺序展示各阶段核心设计、高潮反推与阶段成果。
7. **剧情段（L3）**：按 `SEQ` 顺序展示局部驱动问题、实际启用的开篇试读窗口设计与章节分配表。
8. **章节细纲（L4）**：按 `CH` 顺序完整呈现每章细纲与推进脉络，戏眼按实际存在内容收录。
9. **场景蓝图（L5，按需）**：按章节归组展示复杂场景的博弈转折。
10. **状态与因果台账**：大纲状态、拟议世界状态变化、关键事件因果依赖与时间线。
11. **信息、伏笔与节奏台账**：知识状态、反转台账、伏笔追踪、未闭环义务、角色状态与压力曲线。
12. **审计与变更记录**：审计报告摘要、变更请求（CR）与版本快照记录。

## 4. 排版与跨环境构建路线

本包的三个脚本负责大纲初始化、结构/字段/ID 引用检查和版本快照，没有 DOCX 构建器、模板引擎、PDF 转换器或页面渲染器。以下为文档制作指导，不代表包内已有自动化实现，也不代表已完成跨环境或实际排版验收。

文档交付可按环境选择：

- **路线 A（宿主文档能力）**：宿主确实提供文档技能时，按该技能规范实施构建、渲染和检查；不假定某个命名技能在所有宿主存在。
- **路线 B（通用制作指导）**：具备文件与命令执行权限时，可安装并调用 `python-docx` 构建 DOCX、LibreOffice 导出 PDF，再选择 `pypdfium2 + Pillow`、依赖 Poppler 的 `pdftoppm` 或其他合适渲染器生成 PNG。转换器、PDF 库与字体均需在实际环境可用；它们不是 Python 标准库，也不由本包分发。使用外部依赖时遵守其各自许可证。

开始前核对可用的构建方式、转换器、渲染器和字体；缺少环节时明确报告尚未完成的工作，不能把结构检查通过写成 DOCX 交付通过。生成后核对完整内容与实际页码，再逐页检查最后一轮渲染。后续若复用世界观技能的排版基础，仍须适配大纲层级、宽表与台账并单独验证，本版本不声称已经复用这些脚本。

### 版面设计要点

- **层级与导航**：使用标准 Word 标题样式（`Heading 1–4`）区分大纲层级与 `ARC / SEQ / CH`，配备自动目录、页眉（项目名与版本号）及页码。
- **正文与表格配合**：总表（如五轨总表、章节分配表、台账）用于横向对比，设置合理列宽、表头底色、单元格内边距与跨页重复表头；单章细纲与故事弧详情采用清晰的标题、项目符号与短段落排版，避免把大段叙述塞入窄长单元格。
- **分页控制**：大模块之间清晰分页，标题开启“与下段同页（`keep_with_next`）”防止孤立在页尾；连续章纲之间按实际篇幅自然排布，避免强制每章分页造成大面积留白。

## 5. 视觉检查与交付

构建完成后，将 DOCX 转换为 PDF 并渲染页面预览图，重点检查：
1. 封面、目录与正文的标题层级、版本号、章节数量是否一致；目录页码与跳转是否对应实际输出。自动目录字段存在不代表已经刷新或页码正确。
2. 宽表格（如五轨总表、因果依赖表）是否清晰可读、无文字截断或出界。
3. 标题是否与正文分离在页尾，章节过渡是否紧凑自然。
4. 锁定版本是否已全部消解 `[待确认] / TODO / TBD` 占位符。

确认无误后向用户交付最终 `.docx` 文件，并附上简明的版本、层级覆盖范围与核对说明。

自动大纲检查、文档创建成功、PDF 转换成功与逐页视觉检查分别报告；没有实际文档和渲染证据时，不得声称已完成排版验收。
