# 大纲 DOCX 最终交付指南

在本次大纲任务完成并需要导出完整阅读文档时读取。日常规划与滚动修改继续以 `大纲/` 与 `追踪/` 中的 Markdown 为主；生成的 DOCX 是对应版本与完成范围的排版级汇编文档，便于通读、审稿或团队分享。

## 1. 交付时机与命名

- **常规交付（`create / expand / repair / change / lock`）**：完成目标层级后汇编生成完整的 DOCX。
- **版本标识**：已锁定版本从对应状态或快照生成（如 `{项目名}_小说大纲_v1.0.docx`）；阶段性方案使用 `draft-YYYYMMDD` 命名并在封面标明草案状态与当前视野。
- **进度记录**：生成后在 `大纲/工作状态.md` 记录文件路径、版本、完成层级与日期。

默认输出路径：

```text
{项目根}/交付/{项目名}_小说大纲_{版本}.docx
```

## 2. 汇编前内容对账

汇编前盘点当前有效内容，确保层级对齐、无残留空壳：

- **基础与工作状态**：`大纲/工作状态.md`、锁版 manifest。
- **世界观接口摘要（若有）**：`大纲/世界观引用.md` 中本书实际引用的规则、结构冲突、剧情种子、语言与日常肌理参考摘要。
- **核心大纲层级（L0–L5）**：只收录当前版本实际启用的内容；未使用的空表自动跳过。
  - `L0 Story DNA`（创作初衷、期待场面、百字核心故事、追读问题与主导驱动力）
  - `L1 故事架构`（五轨总表、人物×情节矩阵、人物决策依据与关系张力、主支线契约）
  - `L2 故事弧（ARC）`（按顺序收录目标、阻力、选择、代价、不可逆后果与阶段保留成果）
  - `L3 剧情段（SEQ）`（驱动问题、升级、选择、后果、开篇试读窗口设计与章节分配表）
  - `L4 章纲（CH）`（按章节顺序完整收录有效章纲与推进脉络，保留精简/展开/余波留白格式）
  - `L5 场景蓝图（SC）`（收录已创建的近期复杂场景蓝图）
- **追踪台账**：实际启用的 `大纲状态.md`、`世界状态变化.md`、`因果依赖.md`、`伏笔.md`、`信息与反转.md`、`未闭环.md`、`压力曲线.md`、`角色状态.md` 与 `大纲变更.md`。

## 3. 自动化构建与排版规范

本技能内置 `scripts/build_outline_docx.py` 汇编脚本（依赖 `python-docx`，可通过 `python -m pip install -r requirements.txt` 安装；三个核心大纲校验/锁版脚本仍仅使用 Python 标准库）：

```bash
# 默认自动识别中文/英文大纲并生成书籍级配色排版的 DOCX
python <skill-dir>/scripts/build_outline_docx.py --root <项目根> --out <项目根>/交付/<项目名>_小说大纲_v1.0.docx --version v1.0

# 显式指定英文分节标题与西文衬线排版
python <skill-dir>/scripts/build_outline_docx.py --root <项目根> --out <项目根>/交付/Outline_v1.0.docx --lang en --version v1.0
```

### 版面设计要点

- **克制书籍配色与层级导航**：采用标准 A4 页面，正文宋体 / Georgia 搭配微软雅黑 `Heading 1–4`（墨黛蓝 `#1B263B`、黛蓝 `#2B4C7E`、玄青灰 `#3D405B`、赭石暗金 `#9C4A1A`），与世界设定集视觉风格一脉相承。
- **键值加粗与宽表自适应**：章纲与故事弧中的 `- 字段名：内容` 自动将字段名加粗突出，提升人类审稿速度；宽表格（五轨总表、因果台账）自动按信息密度分配列宽并开启跨页重复表头（`tblHeader`），自动跳过未填写的空壳表。
- **分页控制**：大模块之间清晰分页，各级标题开启“与下段同页（`keep_with_next`）”，连续章纲自然排布避免大面积空白。

## 4. 视觉核验与交付

在具备 LibreOffice 与 PDF 渲染器的环境中，可将生成的 DOCX 转为 PDF 并渲染页面预览图，重点检查：
1. 封面、分节标题、版本号与正文范围是否一致。
2. 宽表格是否清晰易读、无异常拥挤或越界。
3. 锁定版本是否已全部消解 `[待确认] / TODO / TBD` 占位符。

确认无误后向用户交付最终 `.docx` 文件，并简述版本与覆盖范围。
